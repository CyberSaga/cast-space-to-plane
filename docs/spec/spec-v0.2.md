## 1. 範圍與已定案決策

| 決策 | 內容 |
| --- | --- |
| 投影方式 | 只做透視（中心投影）；正投影不在本次範圍 |
| 操作模型 | **板子為主**：使用者只操作板子的「方向」與「離場景的距離」；眼睛 E 由這兩者算出，唯讀 |
| 方向 | 橘色圓環：整組（板子加眼睛）繞旋轉中心環繞，板子可轉到物體的任何一側 |
| 距離 | 藍色箭頭：板子前後移，眼睛固定在板子後方 D，跟著一起移 |
| 眼睛到板子 D | 焦距旁的滑桿（畫面以外），不在畫面內拖動：非主要功能 |
| 右窗操作 | **唯讀**：任何拖動（左、右、中鍵、Shift、觸控單指或雙指、手寫筆）與滾輪都不觸發任何操作，也不報錯、不提示、不進復原堆疊；板子的所有操作都在左窗與工具列（§5.9） |
| 平移 | 整組沿板子平面的位移，旋轉中心不變；不再有手動操作，只來自載入規則（§4.2），點選物體當旋轉中心與一鍵視圖會把它歸零；與更換旋轉中心是不同的概念 |
| 工具列預設 | 圖層與「Hidden lines」「3D view」是頁面層級的狀態，預設值見 §2.1，載入場景不改變它們 |
| 滾轉 | 與焦距、D 並排的滑桿：沿視線那一條軸轉動畫面，眼睛不動；與「自由滾轉」（環繞時 up 跟著整組轉）不同 |
| 旋轉中心 | 預設場景中心；可點選物體改為該物體；更換不進復原堆疊 |
| 版面 | 旁觀視角與作圖畫面左右並排；關閉開關時作圖畫面佔滿全寬，與現況相同 |
| 輔助輸入 | 平面方程式欄位、六個一鍵視圖（前後左右上下） |
| 核心 | 核心不知道「板子為主」：網頁把狀態換算成 `picture_plane` 相機區塊（§4.1），A、B 段不變；Python 與 TypeScript 各一份換算函式，納入一致性測試集 |

這個模型的幾個事實：

1. 眼睛不動時，板子沿法線平移只會等比縮放畫面，畫面形狀不變。本模型讓眼睛固定在板子後方，隨板子一起移動，所以距離會改變畫面：近則物體大、透視強，遠則物體小、透視弱。
2. 固定視角：`focal_length_mm`、`frame_mm` 不隨圓環與箭頭改變；D 只由滑桿改變，所以拖把手時畫框在 3D 裡的實際大小不變。
3. 沒有平移時眼睛正對旋轉中心，旋轉中心（預設為場景中心）落在畫框正中央；平移後偏離正中央，偏移量就是平移量。
4. 因此不需要「自動移位」：平移垂直於 f，旋轉中心沿 f 的深度永遠是 R = g + D ≥ 0.8 m。先前草案的「拖 E」「自動移位」「繞 E 轉頭」模式已取消。

## 3. 旁觀視角

打開後左窗是一台獨立的旁觀相機（垂直視角 40°），右窗是現有的作圖畫面。作圖相機只由板子的操作與焦距滑桿改變，旁觀相機怎麼轉都不影響輸出。

| 元素 | 內容 | 預設 |

| 視錐 | 眼睛經過畫框四角的四條線，往外延伸 1.9 倍距離（虛點） | 顯示 |
| 主點 | 眼睛到平面的垂足 Q，即畫框中心 | 顯示 |
| D 線 | 眼睛到 Q 的虛線，標示目前的 D | 顯示 |
| 旋轉中心 | 菱形標記；點選物體為中心時標籤加物體名 | 顯示 |

| 圓環與箭頭 | 橘色虛線圓環（半徑為畫框半對角線的 1.03 倍，最小 0.45 m）；藍色箭頭由 Q 指向眼睛，長度 clamp(0.55·D, 0.3, 1.4) m，尖端為把手，標籤「板子距離」 | 顯示 |

頂點射線就是雙重投影：光源把 P 投到地面得 S，眼睛再把 P、S、L、F 投到畫面，作圖線是兩次投影疊在一起的結果。

旁觀相機的操作：左拖繞轉、滾輪或雙指縮放。左窗是唯一可以操作板子與旁觀相機的畫面。初始位置從斜上方 28° 看。點擊優先序：箭頭尖端 > 圓環 > 物體（旋轉中心為「點選物體」時）> 空白處（繞轉）。把手命中半徑：滑鼠 14 px、觸控 26 px（圓環為其 0.8 倍）。

旁觀相機的取景（「旁觀視角取景」按鈕，另在套用方程式、一鍵視圖、重設、復原、更換旋轉中心後自動執行，拖曳中不執行）：保留方向，把目標移到下列點的重心並拉遠到 clamp(2.3 × 最大半徑, 6, 60) m。這些點包含眼睛、Q、場景中心、光源、場景中心的地面點、畫框四角。

## 4. 平面模式：資料與換算（規範性）

### 4.1 核心相機區塊

相機區塊多一種寫法：`position` 加 `picture_plane`，與 `target` 形式、`yaw/pitch` 形式三擇一。平面沿用受影面的慣例 `n·X + offset = 0`。

```json
"camera": {
  "position": [0.37, -2.0, 0.9],
  "picture_plane": {"normal": [0, 1, 0], "offset": -2.0},
  "focal_length_mm": 20, "frame_mm": [36, 24], "near_m": 0.05
}
```

數值為 demo 場景的起始狀態：平面 y = 2，眼睛在場景中心正後方 R = 7.84 m。

| 欄位 | 規格 |
| --- | --- |
| `normal` | 非零向量，讀入時正規化；正負號不影響結果 |
| `offset` | 平面常數；平面通過 `position` 時為輸入錯誤 |
| `up` | 選填；畫框的「上」，投影到平面上使用。省略時取世界 +z 的投影，平面水平時改取 +y；投影後為零向量時為輸入錯誤。網頁在鎖水平且滾轉為 0 時省略它，其餘情況寫入相機最終的 up（§4.2） |
| `focal_length_mm`、`frame_mm`、`shift_mm`、`near_m` | 意義不變；網頁 UI 的 `shift_mm` 仍固定為 0 |

換算在 B 段之前進行，產生一個 `target` 形式的相機區塊，之後完全走現有的 `camera_matrix`（v0.1 §5.4）：

```latex
s = \hat n \cdot E + \mathrm{offset},\quad D = |s|,\quad f = -\operatorname{sign}(s)\,\hat n,\quad Q = E - s\,\hat n,\quad \text{target} = E + f
```

- `roll_deg` 取「`camera_matrix` 由 f 算出的預設 up」到畫框 `up` 的有號角，繞 f 量測；`picture_plane` 形式不發出 `CAMERA_LOOKING_ALONG_UP` 警告，因為 up 已明確給定。
- 畫框在平面上的實際大小為 `frame_mm × D / focal_length_mm`（公尺）。
- 幾何文件記錄正規化後的 `picture_plane`，另附 D、Q、畫框公尺尺寸與方程式字串；「Download scene」保留 `picture_plane` 形式，Python 命令列可重現同一張圖。

### 4.2 網頁的板子狀態（rig，只在網頁，核心不知道）

狀態：方向 `f`（單位向量，由眼睛指向板子）、選填的自由滾轉向量 `up`、板子離旋轉中心的距離 `g`、眼睛到板子的距離 `D`、平移 `(a, b)`、滾轉 `ρ`、焦距 `focal`，加上旋轉中心 `P`。眼睛與平面常數都是算出來的：

```latex
L = a\,r_0 + b\,u_0,\qquad E = P - (g + D)\,f + L,\qquad Q = E + D\,f,\qquad c = f \cdot P - g
```

- 基底 (r₀, u₀)：u₀ 取 `up` 投影到垂直 f 的平面（沒有 `up` 時取世界 +z 的投影，f 平行 z 時改取 +y），正規化；r₀ = normalize(f × u₀)；u₀ = r₀ × f。這是滾轉前的基底。
- 相機最終基底：r = cos ρ · r₀ + sin ρ · u₀，u = −sin ρ · r₀ + cos ρ · u₀（同 `camera_matrix` 的 roll 慣例）。
- 平移以滾轉前的基底記錄：環繞時基底跟著整組轉，(a, b) 不變，所以眼睛仍是剛體繞 P；滾轉時基底不動，所以眼睛不動。L 垂直於 f，平面常數 c 不受平移影響。

- 平面為 `f·X = c`。換成核心相機區塊：`position = E`、`normal = f`、`offset = −c`、`up = u`（鎖水平且 ρ = 0 時省略）；此時 s = −D，核心算出的 forward 正是 f。
- g 可以為負：板子越過旋轉中心，這時場景的一部分在眼睛與板子之間。
- 眼睛到旋轉中心的距離 R = g + D，限制在 [0.8, 40] m，所以 g ∈ [0.8 − D, 40 − D]。
- 初始狀態：f = +y、g = P_y − 2、D = 4 m、平移 (0, 0)、滾轉 0°、焦距 20 mm，即平面 y = 2，眼睛在場景中心正後方。
- D 由焦距旁的滑桿調整（0.5–12 m，步進 0.1 m），圓環與箭頭都不改變它。調 D 時板子不動（g、c 不變），眼睛沿 f 前後移；D 夾在 [max(0.5, 0.8 − g), min(12, 40 − g)]，使 R 仍在範圍內。
- 旋轉中心 P：預設為 A 段包圍盒中心；選「點選物體」後為該物體的包圍盒中心。更換 P 後立即依 `E = P − (g + D) f` 重算眼睛，畫面會跳動；更換不進復原堆疊。
- 載入規則（demo 未涵蓋）：任何相機載入後，`f` = forward、`P` = 場景中心、`D` = `picture_plane` 的距離（其他形式取 4 m）、`g = f·(P − E) − D`。眼睛不在通過 P 的軸線上時，偏差直接成為平移（投影到基底得 a、b），畫面不變。滾轉 ρ 取相機的 `roll_deg`（`picture_plane` 形式則為預設 up 到給定 up 的有號角），`up` 清空（鎖水平）。D 超出滑桿範圍時夾限並提示。
- M9 只有唯讀的旁觀視角，板子位置用同一個載入規則從目前的相機推出：M7 的 orbit 狀態取 P = target、R = distance、D = 4 m、g = R − D、平移 (0, 0)、ρ = roll。

### 4.3 畫面點反投影回平面

旁觀視角畫線稿、主點、畫框都用它。r′、u′ 為 R 的前兩列，s_c = canvas_w / frame_w，focal 為焦距 mm：

```latex
X(u, v) = E + D\left[\frac{u - u_0}{\mathrm{focal}\cdot s_c}\,r' + \frac{v - v_0}{\mathrm{focal}\cdot s_c}\,u' + f\right]
```

對 X 再投影必須回到 (u, v)，誤差 < 1e-9 mm。

方程式字串：法線平行座標軸時寫成「x = 1.00」（取正向座標軸，數值依法線正負號換算），否則寫成正規化的「0.707x + 0.707y = 1.200」（第一個非零係數取正），省略係數絕對值小於 5e-4 的項，係數三位小數。

### 5.2 圓環：環繞

靈敏度 κ = 0.32°/px。抓住圓環上的點，它會跟著手指走：轉動的整組包含板子與眼睛，樞軸為旋轉中心 P，D、g、R 不變。

符號規則：記按下時抓到的圓環點相對 P 的向量 w，旁觀相機的右、上軸為 r_c、u_c；`sgn(axis, dir, flip)` 回傳 sign(±dir·(axis × w))（flip 時取負號），絕對值小於 1e-6 時取 +1。

- **鎖水平（預設）**：先繞世界 z 軸轉 `sgn(ẑ, r_c, 否) · Δx · κ`；再算轉完後的水平右軸 r₁，令 p₀ = asin(f_z)，把仰角改到 `clamp(p₀ + sgn(r₁, u_c, 是) · Δy · κ, ±89.9°)`，即繞 r₁ 轉 p₁ − p₀。`up` 為空，地平線永遠水平。
- **自由滾轉**：繞旁觀相機的上軸轉 `sgn(u_c, r_c, 否) · Δx · κ`，再繞右軸轉 `sgn(r_c, u_c, 是) · Δy · κ`；`up` 向量同步旋轉（用於 `picture_plane.up`）。
- 吸附：若 f 與某軸夾角 < 5°，以最小旋轉（繞 f × 軸）把 f 轉到該軸，`up` 同步旋轉。吸附後的 f 為精確的軸向量，所以可到達俯視與仰視。

### 5.3 箭頭：板子距離

按下時記錄 g₀ 與螢幕向量 v：尖端沿 +f 移動 1 m 在螢幕上的位移（px/m）；尖端或該點在旁觀相機背後時取 v = (0, −40)。拖動位移 Δ（px）換成公尺數：

```latex
t = \frac{\Delta \cdot v}{\max(|v|^2,\ 64)},\qquad g' = \operatorname{clamp}(g_0 - t,\ R_{\min} - D,\ R_{\max} - D)
```

t 為板子朝場景移動的公尺數，所以朝場景拖會縮小 g。吸附：f 為 ±e_i 時，令 s_g = f_i 的正負號、`c = f·P − g`、`c′ = s_g · round(10 · s_g · c) / 10`，再令 `g′ = f·P − c′`（夾限）。

### 5.4 旋轉中心

兩種：**場景中心**（預設）與**點選物體**。選「點選物體」後，在左窗點一下物體（位移 < 5 px 的點擊）即設為旋轉中心，多個物體重疊時取離旁觀相機最近者；尚未選取時暫用場景中心。更換旋轉中心後眼睛移到新的軸線上，保留 f、g、D，並自動取景；更換不進復原堆疊。

### 5.5 一鍵視圖

六個按鈕把 f 設為下表的軸向，`up` 清空（鎖水平）或重算（自由滾轉），並清除平移與滾轉；g 與 D 不變，眼睛 `E = P − (g + D) f`。水平的四個視圖眼高等於旋轉中心高度。

| 視圖 | f | 說明 |
| --- | --- | --- |
| 前 | +y | 從 −y 看向 +y |
| 後 | −y | 從 +y 看向 −y |
| 左 | +x | 從 −x 看向 +x |
| 右 | −x | 從 +x 看向 −x |
| 上 | −z | 從上往下看（平面視圖） |
| 下 | +z | 從下往上看 |

### 5.6 平面方程式欄位（輔助）

平時即時顯示目前平面；可直接輸入後按 Enter 或「套用」，並提供 x=1、y=2、y=−3、z=3、x+y=3 的快速按鈕。

- 接受 x、y、z 的一次式，兩邊都可有項：`x=1`、`y = -2.5`、`2x - y + 3 = 0`、`x + y = 2`。
- 解析為單位法線 n 與常數 d（`n·X = d`）後換成板子狀態：令 `s_d = d − n·P`，`f = −n`（s_d ≥ 0）或 `n`（s_d < 0），`g = |s_d|`。也就是永遠選板子位於眼睛與場景之間的那一側。
- 平移與滾轉保留；L 垂直於 f，平面仍是輸入的那一個。
- 語法錯誤、全無 x/y/z、或 `g + D > 40`：欄位變紅並說明原因，保留原平面。
- 在 D = 4 m、旋轉中心為場景中心時，輸入 `y=2` 得到起始視角（眼睛在 y = −2）；輸入 `x=1` 得到從 +x 側看過去的視角。

### 5.7 復原、重設、焦距

- 復原堆疊最多 50 步：每次實際改變了板子的拖動（左窗圓環與箭頭）、一鍵視圖、方程式套用、重設各一步，「鎖水平」從關切回開時一步。按下但沒有移動不記。旁觀相機、焦距、D、滾轉、旋轉中心更換不進堆疊。復原後三個滑桿同步顯示還原的值。
- 重設：回到初始狀態（含焦距 20 mm、D 4 m、平移 0、滾轉 0°）、旋轉中心回場景中心、旁觀相機回初始方向並取景。
- 焦距滑桿 12–80 mm（預設 20）：改變視野與畫框大小，眼睛與板子都不動。
- D 滑桿與焦距滑桿並排，規則見 §4.2；滾轉滑桿也並排，規則見 §5.9。

### 5.8 讀數

兩窗下方顯示：投影平面（方程式）、板子離場景 g 與觀看距離 R、眼睛 E 的座標（唯讀）、眼睛到板子 D、平移 (a, b) 與滾轉、畫框公尺大小。另有「這次拖動右窗畫面變動」（拖動指左窗的圓環或箭頭；右窗本身不能拖）：對所有物體頂點，計算拖動開始與現在的畫面座標最大位移（畫框 mm，背後的點略過）；小於 0.005 mm 顯示「0.00 mm（不變）」。

### 5.9 右窗唯讀；滾轉

**右窗（作圖畫面）是唯讀的。** 在右窗上的任何拖動（左、右、中鍵、Shift 加拖、觸控單指或雙指、手寫筆）與滾輪都不觸發任何應用操作，而且是安靜地不做事：不報錯、不跳提示、不進復原堆疊、不改相機、不顯示抓取游標。右窗不呼叫 `preventDefault`（滾輪與觸控交給瀏覽器，頁面照常捲動；`touch-action` 維持瀏覽器預設），也不再攔截右鍵選單。檔案拖放在整個頁面照舊有效。

M10 初稿所定的右窗對應（左拖＝圓環、滾輪或捏合＝藍色箭頭、右拖、Shift 拖或雙指一起移動＝平移，沿用 M7 的手感）全部移除。板子與旁觀相機只在左窗操作：

| 操作 | 效果 |
| --- | --- |
| 左窗：圓環、箭頭、旋轉中心為「點選物體」時的物體、空白處左拖、滾輪或雙指 | 見 §5.1–§5.4 與 §3 |
| 工具列與面板：滑桿（焦距、D、滾轉）、六個一鍵視圖、方程式欄位、復原、重設、鎖水平、旋轉中心選擇 | 見 §5.5–§5.7 |

- **平移 (a, b) 不再能手動編輯**：它只來自載入規則（§4.2：眼睛不在通過 P 的軸線上時，偏差直接成為平移），並在點選物體當旋轉中心（§5.4）與一鍵視圖（§5.5）時歸零；環繞、箭頭、D 與滾轉都保留它。因為沒有手動平移，讀數的 (a, b) 在多數情況下是 0。
- 旁觀視角關閉時只剩右窗，這時沒有任何拖曳或滾輪可以改變相機；相機由工具列與面板（上表第二列）調整，需要拖曳圓環與箭頭時打開旁觀視角。
- **滾輪（左窗箭頭）不等於焦距**：兩者都讓物體變大，但焦距是等比放大，遠近比例不變；箭頭是拉近，遠近比例改變、透視變強。例：demo 中近處木箱放大 1.5 倍時，焦距讓遠處方塊與木箱的高度比維持 0.542，拉近則降為 0.458。所以焦距維持獨立的滑桿。
- **平移不等於更換旋轉中心**：平移讓整組沿板子平面位移，之後環繞仍繞原來的旋轉中心；更換旋轉中心（§5.4）則讓眼睛跳到新中心的軸線上。
- **滾轉不等於自由滾轉**：滾轉是對結果沿視線這一條軸加一個角度；自由滾轉是環繞時 up 跟著整組轉。鎖水平時，滾轉讓地平線相對水平傾斜 ρ，環繞時保持這個傾斜。滾轉滑桿（−180°～180°）繞眼睛的視線轉 ρ，眼睛與板子不動。
- 圓環與箭頭的拖動在放開時結算一步復原。

## 6. 退化情況

| 情況 | 處理 |
| --- | --- |
| 場景中心在眼睛背後 | 不會發生：旋轉中心沿 f 的深度永遠是 R ≥ 0.8 m |
| 場景只有部分在眼睛背後（R 小、物體大） | 不處理，照現有近平面裁切 |
| 物體介於眼睛與板子之間（含 g < 0） | 照畫，比實物大；作圖法不受影響 |
| 方程式使 `g + D > 40` | 拒絕，保留原平面 |
| 拖箭頭超出範圍 | 夾在 R_min = 0.8 m 與 R_max = 40 m |
| 平面水平（f = ±z） | up 預設 +y；沒有地平線 |
| 調 D 使 R 超出範圍 | 滑桿夾限 |
| 平移後旋轉中心不在畫框正中央 | 正常；偏移量等於平移量 |
| 平移讓旋轉中心離開畫框 | 照算；環繞仍繞旋轉中心 |
| 眼睛低於地面（E_z < 0） | 照算，提示「眼睛在地面下方」 |
| 鎖水平拖曳到仰角極限 | 夾在 ±89.9°；一鍵視圖與吸附可到精確的 ±90° |
| 抓到的圓環點與樞軸的螢幕位移幾乎為零 | 轉動方向取 +1 |

### A.3 一致性測試集

依 `CLAUDE.md`：不得手改 `expected/`（`protect_expected.sh` 會擋）；先加案例、再產生、檢視差異、最後才改程式；改變 expected 位元組的變更必須在同一個變更內更新 TS port，兩個執行器在同一個 commit 都要通過。

- 新鍵只在 `picture_plane` 形式的文件出現：`camera.picture_plane = {normal, offset, up, distance, foot, frame_m, equation}`。其他 60 個既有案例的 expected 不變，不需要像 v4 那樣整組重新產生（D75；同 M6「多光源鍵只出現在多光源文件」的前例）。
- 新鍵都是世界座標或字串：數值走既有的 1e-9 相對容差，`equation` 完全相等；`rules.json` 不必改。
- 新增三個案例：`camera_picture_plane_vertical`（y = 2）、`camera_picture_plane_tilted`、`camera_picture_plane_horizontal`（z = 3 由上往下）。每個案例的畫面座標必須與手寫等價 `target` 相機的既有輸出一致，這是交叉驗證（`tests/test_picture_plane.py`）。案例不要放在 `tests/conformance/README.md` 規則 3 列出的 ulp 放大邊界上；水平平面案例要先確認。
- 流程：worker 把候選場景放在 `tests/fixtures/v8_candidates/`，不碰 `tests/conformance/`；由 merger 在合併後的分支上對每個案例執行 `python3 tools/regen_conformance.py --case NAME --reason "..."`，再執行 `python -m tests.build_identity --write`。重新產生時要先 `--dry-run` 確認既有 60 案是 0 changes。
- 版本與計數：一致性測試集 v7 → v8，案例 60 → 63；README、USAGE、`CLAUDE.md` 的案例數與版本同步。
- 容量：`expected/` 目前約 2.58 MiB，上限 3 MiB，剩約 0.42 MiB。相機類案例約 25–55 KB，三案約 100–165 KB，可容納；場景保持最小。
- 板子為主的 rig 只在網頁，不進核心的一致性測試集；核心只看到眼睛與平面。
- 反投影往返、等價、平移不變用 pytest 與 hypothesis 做屬性測試，不進一致性測試集。

### A.5 已知陷阱

- `camera_matrix` 對 forward ∥ 世界 up 會發出 `CAMERA_LOOKING_ALONG_UP`；`picture_plane` 形式（例如水平平面）必須抑制它（D74），而不是新增警告代碼：警告代碼是封閉清單，新增就是合約變更。
- 相機慣例不能「修正」：R 的列為 (right′, up′, forward)，det R = −1 是刻意的（D14）。
- 核心只 import numpy；`resolve_picture_plane` 與 `unproject_to_plane` 不得引入其他相依。
- 只換相機的重算不得變慢：`resolve_picture_plane` 是常數時間，但不要讓它破壞 `camera_only` 的 TS 效能閘門（< 100 ms）與 Python 的既有基準；不得放寬閘門。
- 網頁必須重用既有的 `camera_matrix` 與 `apply_camera_block`；demo 是 Canvas 2D 的獨立實作，只能當行為與數學的參考，不要整段貼進 `web/`。
- 旁觀視角開關關閉時，輸出（SVG、JSON）必須與現況逐位元相同。
- 語言：程式碼、docstring 與合約用英文；規格、DECISIONS、USAGE、README、一致性測試集文件用繁體中文，各檔維持自己的語言。
