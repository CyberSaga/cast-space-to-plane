本文件是 `spec-v0.2.md` 的**增補**，不取代它。v0.2 的名詞（§0.1）、板子模型（§1、§4）、操作（§5）、退化情況（§6）在本文件沒有明說修改的地方一律照舊。v0.2 的主角是**板子**（投影平面）；本文件開啟另一個方向「編輯場景」，第一步只做一件事：在網頁裡轉動場景中的**一個**物體。相機、板子、眼睛、光源、受影面全部固定，只有被選的物體改變。

- 點擊判定為位移 < 5 px（v0.2 §5.4），把手命中半徑滑鼠 14 px、觸控 26 px（圓環為其 0.8 倍）。
- 復原堆疊最多 50 步（v0.2 §5.7）。
- 只有左窗（旁觀視角）可以操作，右窗唯讀（v0.2 §5.9）。
- 預覽時旁觀視角收起，只剩工具列與面板可用（v0.2 §2.2，D80）。

**以引用方式修訂 v0.2 的三處**（v0.2 本文不改）：

- v0.2 §5.4：轉動模式開啟時，點選物體的意義是「選取轉動對象」，不再是「更換旋轉中心」；旋轉中心的點選物體功能在此模式下暫停。

核心（Python 與 TypeScript 移植）、一致性測試集與所有未操作時的輸出都不變：本功能只在網頁。轉動後的場景是合法的場景，核心照算，下載的場景檔與命令列重現同一張圖。

## 2. 資料與換算（規範性）

物體的姿態是 `transform: {position, rotation_deg}`，世界座標 = R·局部座標 + p，其中 p = `position`，R = Rz(rz)·Ry(ry)·Rx(rx)（Z-Y-X Euler，`rotation_deg = [rx, ry, rz]`，v0.1 §5）。核心對角度範圍沒有限制，任何有限數都合法。

### 2.1 旋轉中心

局部包圍盒中心 `c_local = bbox_centre({Rᵀ(v − p) : v ∈ 該物體 A 段紀錄的世界頂點})`，即把世界頂點換回局部座標再取軸對齊包圍盒的中心。它只依賴形體本身，與物體載入時的姿態無關：同一個稜柱以 rz = 0 與 rz = 50° 載入，`c_local` 相同。載入場景時按物體 id 算一次並快取，直到重新載入。世界中心 `c_w = R·c_local + p`；轉動過程中 `c_w` 保持不動，面板的「中心」讀數就是它。

### 2.2 拖動：套用世界軸旋轉 Q

Q 是繞世界軸 `axis` 轉 θ 的旋轉矩陣（右手定則）。以按下時的姿態 (R, p) 為底，用總位移換算 θ，不累加：

```latex
R' = Q\,R,\qquad p' = c_w + Q\,(p - c_w)
```

繞世界 z 軸時 rz 恰好加上 θ，rx、ry 不變；繞 x 或 y 軸時三個 Euler 角都會改變，這是 Z-Y-X 慣例的必然結果，不是錯誤。要設定精確的 Euler 值，用數值欄。

### 2.3 數值欄

使用者輸入 (rx, ry, rz)，算出 R′ = Rz(rz)·Ry(ry)·Rx(rx)，`c_w` 不動：

```latex
p' = c_w + R'\,R^{\mathsf T}\,(p - c_w)
```

拖動與數值欄對同一個目標姿態得到相同的 R′ 與 p′。

### 2.4 矩陣換回 Euler（ZYX 分解）

`euler_zyx_from_matrix(R) → [rx, ry, rz]`（度）：`ry = atan2(−R₂₀, hypot(R₀₀, R₁₀))`，值域 [−90°, 90°]。一般情況：`rz = atan2(R₁₀, R₀₀)`、`rx = atan2(R₂₁, R₂₂)`。萬向鎖（`hypot(R₀₀, R₁₀) < 1e-9`，即 ry = ±90°）時 rx 與 rz 繞同一條軸，無法分開，規定 `rx = 0`，`rz = atan2(−R₀₁, R₁₁)`。Euler 角不唯一，所以正確性以**矩陣往返**判定：`euler_zyx_matrix(euler_zyx_from_matrix(R)) ≈ R`，不比較角度本身。

### 2.5 顯示與寫出

面板顯示取 0.1°，範圍 (−180°, 180°]，**不做角度展開**：繞 z 連續轉過 180° 時讀數從 180° 跳到 −180°，170° 加 30° 顯示 −160°，這是定義，不是錯誤；比較兩個角度要模 360。下載的場景檔寫出完整 double，不四捨五入。吸附把拖動角 θ 對齊到 `OBJECT_SNAP_DEG = 15` 的倍數。

## 3. 操作

### 3.1 轉動模式與命中順序

工具列的「轉動物體」切換鈕（預設關）。開啟時：左窗命中順序為**物體圓環 > 物體（點擊選取，位移 < 5 px）> 空白處（旁觀環繞）**；板子的橘色圓環與藍色箭頭隱藏並停用；旋轉中心的「點選物體」暫停。關閉時恢復板子把手，物體圓環隱藏，已選的物體仍保留在面板。左窗操作表多一列：

| 操作 | 效果 |
| --- | --- |
| 左窗（轉動模式）：物體圓環拖動、點選物體、空白處左拖、滾輪或雙指 | 見 §3.2、§3.1、v0.2 §3 |

### 3.2 三個圓環

選取物體後，在 `c_w` 周圍畫三個圓環：x 紅、y 綠、z 藍，各在垂直於該世界軸的平面上，半徑 `1.2 × ½ × 包圍盒對角線`，下限 0.3 m，72 段；拖動中的環畫粗。

拖動的角度沿用 v0.2 §5.2 的規則，不用 atan2 掃過角：按下時記抓到的環點相對 `c_w` 的向量 w、旁觀相機的右、上軸 r_c、u_c。切線 `t = axis × w`，螢幕切線 `t_s = (t·r_c, −t·u_c)` 正規化；`θ = κ · (Δ · t_s)`，其中 Δ 是指標總位移（px）。`|t_s| < 1e-6`（環側視）時取 `t_s = (1, 0)`。再吸附（Alt 暫停），再依 §2.2 套用。

### 3.3 面板「物體」區

- 物體下拉選單：與左窗點選同步；只有一個物體時預設選它。
- rx/ry/rz 數值欄與「套用」：Enter 或按鈕生效（§2.3）；輸入不是有限數的欄位變紅、保留原值，不改變場景。
- 「還原此物體」：回到載入時的 transform，一步復原。
- 「落地」：只在 `receivers[0]` 是無界平面（`type: "plane"`）時顯示。沿其法線平移物體，使新 A 紀錄中所有頂點到該平面的最小有號距離為 0，一步復原。
- 「中心」讀數 `c_w`，以及 §3.5 的慢場景提示。
- 預覽時左窗收起，只能用面板操作。

### 3.4 復原

復原堆疊由板子與物體共用，最多 50 步。物體的每一步記 `(id, before)`：一次實際改變了姿態的圓環拖動、一次數值欄套用、「還原此物體」、「落地」各一步；按下後沒有移動、或姿態與提交前完全相同，不記。「重設」（v0.2 §5.7）維持只重設板子，不動物體。復原物體步驟時，A 段重算成功才取出該步驟（先看再取），失敗則歷史不變。

### 3.5 拖動生命週期

- **按下**：記按下時的 transform `t₀`、場景 `scene₀` 與 A 段紀錄 `A₀`（保留引用，不重算）、手勢序號。
- **移動**：只更新待處理姿態，不算 A 段；下一個影格開頭，若待處理姿態屬於現行手勢，就算一次 A 段，再算 B、C。每格最多一次。
- **放開**：取最後一筆待處理姿態，**同步**算 A 段並提交，成功後才記復原；與已提交姿態相同則不記。不等影格，所以「按下、移一次、立刻放開」也提交最後的姿態。
- **取消**（第二指落下等）：手勢序號作廢，之後到來的影格看到過期序號就不套用；還原 `scene₀`、`A₀`、`PlaneSession` 的頂點與中心，以及左右兩窗的三維群組矩陣；不記步驟。
- **A 段例外**：轉動後的場景合法，核心對退化只警告不丟例外，所以例外代表核心的錯誤。處理：不提交該姿態，保留已提交的姿態與歷史，三維矩陣還原為已提交的值，錯誤面板顯示「核心重算失敗，請回報」。
- **慢場景**：`LIVE_STAGE_A_MS = 150`。載入時 A 段耗時超過它的場景，拖動中只更新三維代理，放開才重算，面板顯示「此場景拖動放開後更新」。範例場景都是即時的。
- B 段沿用拖動中的簡化：拖動中關 umbra 與 hidden lines，放開時完整計算。

## 4. 退化情況

| 情況 | 處理 |
| --- | --- |
| 轉動使物體穿過地面（繞 x 或 y 軸轉） | 照算；核心發 `OBJECT_BELOW_RECEIVER`（預期）並裁切；可按「落地」 |
| 萬向鎖（ry = ±90°） | rx 取 0、rz 由 `atan2(−R₀₁, R₁₁)` 解（§2.4）；矩陣往返成立，讀數可能與使用者輸入的 (rx, rz) 不同但姿態相同 |
| 圓環側視（切線的螢幕投影 < 1e-6） | `t_s = (1, 0)`（§3.2） |
| 載入時 A 段 > 150 ms | 拖動中只動三維代理，放開才重算（§3.5） |
| 板子的旋轉中心 `rig.P` 正指向被轉的物體 | `rig.P` 留在原位，不跟著更新（P 存在 rig，不進物體復原）；要重新置中就再點一次該物體 |
| 對稱形體（球）繞自身軸轉 | 照算；輸出不變 |
| 數值欄輸入空白、NaN、無限大 | 欄位變紅，保留原值 |
| 物體的 `rotation_deg` 超出 (−180°, 180°] 的載入值 | 照算；面板顯示換算後的值，只有在使用者操作後才寫入新的值 |
