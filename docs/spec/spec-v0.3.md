## 2. 資料與換算（規範性）

物體的姿態是 `transform: {position, rotation_deg}`，世界座標 = R·局部座標 + p，其中 p = `position`，R = Rz(rz)·Ry(ry)·Rx(rx)（Z-Y-X Euler，`rotation_deg = [rx, ry, rz]`，v0.1 §5）。核心對角度範圍沒有限制，任何有限數都合法。

### 2.1 旋轉中心

局部包圍盒中心 `c_local = bbox_centre({Rᵀ(v − p) : v ∈ 該物體 A 段紀錄的世界頂點})`，即把世界頂點換回局部座標再取軸對齊包圍盒的中心。它只依賴形體本身，與物體載入時的姿態無關：同一個稜柱以 rz = 0 與 rz = 50° 載入，`c_local` 相同。載入場景時按物體 id 算一次並快取，直到重新載入。世界中心 `c_w = R·c_local + p`；轉動過程中 `c_w` 保持不動，面板的「中心」讀數就是它。

### 2.2 拖動：套用世界軸旋轉 Q

Q 是繞世界軸 `axis` 轉 θ 的旋轉矩陣（右手定則）。以按下時的姿態 (R, p) 為底，用總位移換算 θ，不累加：

```latex
R' = Q\,R,\qquad p' = c_w + Q\,(p - c_w)
```

繞世界 z 軸時 rz 恰好加上 θ，rx、ry 不變；繞 x 或 y 軸時三個 Euler 角都會改變，這是 Z-Y-X 慣例的必然結果，不是錯誤。要設定精確的 Euler 值，用數值欄。

### 2.3 數值欄

使用者輸入 (rx, ry, rz)，算出 R′ = Rz(rz)·Ry(ry)·Rx(rx)，`c_w` 不動：

```latex
p' = c_w + R'\,R^{\mathsf T}\,(p - c_w)
```

拖動與數值欄對同一個目標姿態得到相同的 R′ 與 p′。

### 2.4 矩陣換回 Euler（ZYX 分解）

`euler_zyx_from_matrix(R) → [rx, ry, rz]`（度）：`ry = atan2(−R₂₀, hypot(R₀₀, R₁₀))`，值域 [−90°, 90°]。一般情況：`rz = atan2(R₁₀, R₀₀)`、`rx = atan2(R₂₁, R₂₂)`。萬向鎖（`hypot(R₀₀, R₁₀) < 1e-9`，即 ry = ±90°）時 rx 與 rz 繞同一條軸，無法分開，規定 `rx = 0`，`rz = atan2(−R₀₁, R₁₁)`。Euler 角不唯一，所以正確性以**矩陣往返**判定：`euler_zyx_matrix(euler_zyx_from_matrix(R)) ≈ R`，不比較角度本身。

### 2.5 顯示與寫出

面板顯示取 0.1°，範圍 (−180°, 180°]，**不做角度展開**：繞 z 連續轉過 180° 時讀數從 180° 跳到 −180°，170° 加 30° 顯示 −160°，這是定義，不是錯誤；比較兩個角度要模 360。下載的場景檔寫出完整 double，不四捨五入。吸附把拖動角 θ 對齊到 `OBJECT_SNAP_DEG = 15` 的倍數。

## 3. 操作

### 3.1 轉動模式與命中順序

工具列的「轉動物體」切換鈕（預設關）。開啟時：左窗命中順序為**物體圓環 > 物體（點擊選取，位移 < 5 px）> 空白處（旁觀環繞）**；板子的橘色圓環與藍色箭頭隱藏並停用；旋轉中心的「點選物體」暫停。關閉時恢復板子把手，物體圓環隱藏，已選的物體仍保留在面板。左窗操作表多一列：

| 操作 | 效果 |
| --- | --- |
| 左窗（轉動模式）：物體圓環拖動、點選物體、空白處左拖、滾輪或雙指 | 見 §3.2、§3.1、v0.2 §3 |

### 3.2 三個圓環

選取物體後，在 `c_w` 周圍畫三個圓環：x 紅、y 綠、z 藍，各在垂直於該世界軸的平面上，半徑 `1.2 × ½ × 包圍盒對角線`，下限 0.3 m，72 段；拖動中的環畫粗。

拖動的角度沿用 v0.2 §5.2 的規則，不用 atan2 掃過角：按下時記抓到的環點相對 `c_w` 的向量 w、旁觀相機的右、上軸 r_c、u_c。切線 `t = axis × w`，螢幕切線 `t_s = (t·r_c, −t·u_c)` 正規化；`θ = κ · (Δ · t_s)`，其中 Δ 是指標總位移（px）。`|t_s| < 1e-6`（環側視）時取 `t_s = (1, 0)`。再吸附（Alt 暫停），再依 §2.2 套用。

### 3.3 面板「物體」區

- 物體下拉選單：與左窗點選同步；只有一個物體時預設選它。
- rx/ry/rz 數值欄與「套用」：Enter 或按鈕生效（§2.3）；輸入不是有限數的欄位變紅、保留原值，不改變場景。
- 「還原此物體」：回到載入時的 transform，一步復原。
- 「落地」：只在 `receivers[0]` 是無界平面（`type: "plane"`）時顯示。沿其法線平移物體，使新 A 紀錄中所有頂點到該平面的最小有號距離為 0，一步復原。
- 「中心」讀數 `c_w`，以及 §3.5 的慢場景提示。
- 預覽時左窗收起，只能用面板操作。

### 3.4 復原

復原堆疊由板子與物體共用，最多 50 步。物體的每一步記 `(id, before)`：一次實際改變了姿態的圓環拖動、一次數值欄套用、「還原此物體」、「落地」各一步；按下後沒有移動、或姿態與提交前完全相同，不記。「重設」（v0.2 §5.7）維持只重設板子，不動物體。復原物體步驟時，A 段重算成功才取出該步驟（先看再取），失敗則歷史不變。

### 3.5 拖動生命週期

- **按下**：記按下時的 transform `t₀`、場景 `scene₀` 與 A 段紀錄 `A₀`（保留引用，不重算）、手勢序號。
- **移動**：只更新待處理姿態，不算 A 段；下一個影格開頭，若待處理姿態屬於現行手勢，就算一次 A 段，再算 B、C。每格最多一次。
- **放開**：取最後一筆待處理姿態，**同步**算 A 段並提交，成功後才記復原；與已提交姿態相同則不記。不等影格，所以「按下、移一次、立刻放開」也提交最後的姿態。
- **取消**（第二指落下等）：手勢序號作廢，之後到來的影格看到過期序號就不套用；還原 `scene₀`、`A₀`、`PlaneSession` 的頂點與中心，以及左右兩窗的三維群組矩陣；不記步驟。
- **A 段例外**：轉動後的場景合法，核心對退化只警告不丟例外，所以例外代表核心的錯誤。處理：不提交該姿態，保留已提交的姿態與歷史，三維矩陣還原為已提交的值，錯誤面板顯示「核心重算失敗，請回報」。
- **慢場景**：`LIVE_STAGE_A_MS = 150`。載入時 A 段耗時超過它的場景，拖動中只更新三維代理，放開才重算，面板顯示「此場景拖動放開後更新」。範例場景都是即時的。
- B 段沿用拖動中的簡化：拖動中關 umbra 與 hidden lines，放開時完整計算。

## 4. 退化情況

| 情況 | 處理 |
| --- | --- |
| 轉動使物體穿過地面（繞 x 或 y 軸轉） | 照算；核心發 `OBJECT_BELOW_RECEIVER`（預期）並裁切；可按「落地」 |
| 萬向鎖（ry = ±90°） | rx 取 0、rz 由 `atan2(−R₀₁, R₁₁)` 解（§2.4）；矩陣往返成立，讀數可能與使用者輸入的 (rx, rz) 不同但姿態相同 |
| 圓環側視（切線的螢幕投影 < 1e-6） | `t_s = (1, 0)`（§3.2） |
| 載入時 A 段 > 150 ms | 拖動中只動三維代理，放開才重算（§3.5） |
| 板子的旋轉中心 `rig.P` 正指向被轉的物體 | `rig.P` 留在原位，不跟著更新（P 存在 rig，不進物體復原）；要重新置中就再點一次該物體 |
| 對稱形體（球）繞自身軸轉 | 照算；輸出不變 |
| 數值欄輸入空白、NaN、無限大 | 欄位變紅，保留原值 |
| 物體的 `rotation_deg` 超出 (−180°, 180°] 的載入值 | 照算；面板顯示換算後的值，只有在使用者操作後才寫入新的值 |

## 7. 修訂（D83，2026-11-01）

本節以引用方式修訂 §1 的「模式」一列、§3.1、§3.3 的預選規則與 §5 冒煙一列，上文原文不改；決策為 `docs/DECISIONS.md` D83，合約為 `docs/ARCHITECTURE.md` §5.6 與 §5.8 的實作註記。

- **不分模式。** 工具列不再有「轉動物體」切換鈕。在左窗點一下物體（位移 < 5 px）就選取它：三個圓環出現，與板子的橘色圓環、藍色箭頭同時顯示，面板「物體」區填好；旋轉中心為「點選物體」時，同一下點擊也設定旋轉中心（v0.2 §5.4 照舊）。點空白處（指標下沒有物體）取消選取，圓環消失。下拉選單照舊可以選取或選「—」取消。
- **命中順序**（按下時）：**已選物體的圓環 > 板子的箭頭尖端 > 板子的圓環 > 物體（點擊選取）> 空白處（旁觀環繞）**；游標提示涵蓋物體圓環。
- **載入不預選**：載入場景時清除選取，只有一個物體的場景也一樣。
- **左窗的「板子」勾選框**（預設勾選，在「視線」旁）：取消勾選時只在左窗隱藏眼睛、板子、畫框與上面的圖、視錐、主點、D 線與 g 線、旋轉中心標記、板子的圓環與箭頭，以及它們的標籤；板子把手不做命中測試，按在那裡就是繞轉或點選。物體圓環照常顯示與拖動，視線照自己的勾選框。右窗、輸出、下載、相機區塊、復原與「整體顯示」都不變；不記復原、不寫進場景；按住板子把手拖動時改變它會被忽略。
- 拖動生命週期（§3.5）、復原（§3.4）、數值欄、套用、還原此物體、落地與預覽時的行為都不變。

## 8. 修訂（D84，2026-11-01）

本節以引用方式修訂 §1 的「操作對象」與「旋轉中心」兩列、§2.1 的旋轉中心、§3.1 的點選、§3.2 的圓環、§3.3 的下拉選單、「還原此物體」與「落地」、§3.4 的復原與 §7 的「不分模式」一項，上文原文不改；決策為 `docs/DECISIONS.md` D84，合約為 `docs/ARCHITECTURE.md` §5.8 的實作註記。

- **群組（網頁專用的場景鍵）。** 物件可以帶選用鍵 `objects[i].group`：非空、不是只有空白、且可以用 UTF-8 寫出（不含落單的代理字元）的字串就是群組名稱，原樣保留（不去掉前後空白）；其他值（沒有、不是字串、空字串、只有空白、含落單的代理字元）視為沒有群組，不報錯也不發警告。它和 `display_color` 一樣只給網頁用：核心忽略它，文件、SVG、警告與一致性測試集都不變；「Download scene」原樣寫回。它與 OBJ 的 `g` 群組、網格的 `data.smooth_groups` 無關；不支援巢狀，也不從幾何推斷群組。
- **單位。** 場景中至少有兩個成員的群組是一個單位；沒有群組的物體、或群組名稱只出現一次的物體，各自是一個單位，行為與 D83 完全相同。
- **點選循環（左窗）。** 點群組中的某個部件：第一下選取整個群組，第二下聚焦到點到的部件，第三下回到整個群組，如此往復；聚焦在某個部件時點同一群組的另一個部件，焦點移到那個部件；從別的群組或沒有群組的物體點過來，先選整個群組。只有點物體外面的空白處才取消選取；拖動旁觀相機與拖圓環都不改變選取。旋轉中心為「點選物體」時，這一下點擊把旋轉中心設在新選取單位的中心（群組為其中心 `c`，部件照舊），不記復原。載入時不預選。
- **下拉選單與面板。** 「物體」下拉選單先列每個群組（例如「miki（整組，18 個部件）」），再列每個物體，選「—」取消；面板另有一行顯示目前選取，例如「已選：miki（整組）」或「已選：arm_l（miki 的部件）」。
- **整組轉動。** 每個群組有中心 `c`：載入時所有成員 A 段世界頂點的軸對齊包圍盒中心，轉動時不動。拖整組的圓環 `Q`：每個成員 `R_i′ = Q·R_i`、`p_i′ = c + Q(p_i − c)`。rx／ry／rz 欄位顯示整組**相對於載入時**的轉動 `G`（載入時為 0, 0, 0）；輸入角度 `e` 時 `Q = euler_zyx_matrix(e)·Gᵀ`，所有成員一起繞 `c` 轉。整組的圓環以 `c` 為中心，半徑由群組包圍盒的半對角線決定，比單一部件的圓環大；圓環只在環帶上命中，點在環內仍然選到底下的部件。
- **部件轉動。** 聚焦在部件時，只轉那個部件（繞它自己的中心，同 §2），群組的 `G` 與 `c` 都不變；部件被拖離後，整組的圓環仍留在原本的中心。
- **還原此物體與落地。** 選取整組時，「還原此物體」讓所有成員回到載入時的姿態，`G` 歸零、`c` 回到原位；「落地」以所有成員的最低點為準，整組沿受影面法線平移同一段距離，`c` 也跟著移動。選取部件時兩者都只作用在該部件。
- **復原。** 整組的一次動作（拖圓環、套用、還原此物體、落地）是一步，記下所有成員的姿態與群組的 `G`、`c`，復原時一起還原；與板子及部件的步驟放在同一個 50 步堆疊裡依相反順序取消。沒有改動任何欄位就按「套用」不做任何事，也不記步驟。
- 核心、TypeScript 移植與一致性測試集（v8／63 例）不變；沒有 `group` 鍵的場景與 D83 的行為完全相同。

## 9. 修訂（D85，2026-11-01）

本節以引用方式修訂 §2.1 的旋轉中心、§3.2 的圓環中心與 §8 的「部件轉動」「還原此物體與落地」，上文原文不改；決策為 `docs/DECISIONS.md` D85，合約為 `docs/ARCHITECTURE.md` §5.8 的實作註記。

- **連動鍵（網頁專用的場景鍵）。** 物件可以帶兩個選用鍵：`objects[i].parent` 是同一個群組中另一個部件的 id（非空、可以用 UTF-8 寫出的字串，原樣保留）；`objects[i].joint` 是恰好三個有限數字 `[x, y, z]`，位於物件的**局部座標**（網格頂點、基本形體在套用 `transform` 之前的座標），所以世界關節 `j_w = R·joint + p` 隨物件一起動。兩者和 `group` 一樣只給網頁用：核心忽略它們，文件、SVG、警告與一致性測試集都不變；「Download scene」原樣寫回，重新載入同一個檔案得到相同的連結與（在轉動後的姿態下）相同的世界關節。格式不對的值視為沒有，不報錯也不發警告。`joint` 可以沒有 `parent`（根部件自己的關節），`parent` 也可以沒有 `joint`。
- **連結何時有效。** `parent` 只在父子兩個物體屬於同一個至少兩個成員的群組時才算；`parent` 是自己、不是場景中的 id、或兩者不在同一組，就當作沒有這個連結。環上每個節點的 `parent` 都被丟掉（掛在環上的樹保留自己的連結），結果與場景順序無關。無效的連結讓那個部件的行為與 D84 完全相同。`joint` 另外判斷：沒有群組的物體或群組只有一個成員的物體若帶 `joint`，它繞自己的關節轉。連結在載入時解析一次，除了每個物體的 `transform` 以外沒有任何持久狀態（沒有關節角度）。
- **部件轉動（修訂 §8「部件轉動」）。** 聚焦在部件 P 時，拖圓環或輸入 rx／ry／rz，P 與它所有的後代（P 在前，其餘依先序、兄弟依場景順序）一起繞同一個世界點剛體轉動；這個點是按下時 P 的世界關節 `j_w`，沒有 `joint` 時是 §2.1 的 `c_w`。P 的關節因此始終留在不動的父部件上；祖先、兄弟與整組的 `G`、`c` 都不動，部件被轉動後整組的讀數與圓環不變。沒有 `joint` 也沒有子孫的部件照 §8 只轉自己。
- **數值欄。** 欄位顯示 P 自己的世界 Euler 角（§2.3、§2.5）。輸入 `r` 套用時，P 的角度精確等於 `r`、位置依 §2.3，其餘成員一起繞同一個點轉 `Q = R′Rᵀ`，所以拖動與輸入到達同一個目標時姿態相同。輸入值與顯示的角度逐分量完全相等（沒有改動任何欄位）時不做任何事，也不記步驟。
- **圓環與讀數（修訂 §2.1、§3.2）。** 部件的三個圓環以它的樞軸為中心（有 `joint` 時是 `j_w`，否則是 `c_w`），半徑仍由部件自己的包圍盒決定；面板的讀數在樞軸是關節時寫「關節 j_w = (x, y, z) m」，否則照舊寫「中心 c_w = …」。部件帶動子孫時，「已選」那一行寫「已選：head（miki 的部件，帶動 6 個部件）」。下拉選單、點選循環與命中順序不變。
- **還原此物體與落地（修訂 §8「還原此物體與落地」）。** 選取部件時，「還原此物體」讓 P 回到它**相對於父部件目前姿態**的載入姿態，整個子樹跟著同一個剛體增量移動，子孫相對於 P 自己的調整保留；沒有父部件，或父部件正好在載入姿態時，P 回到載入的 `transform`。P 已在目標姿態時（有父部件的部件容許 1e-9 的差：位置單位為公尺，旋轉矩陣元素沒有單位）不做任何事、不記步驟，按鈕停用。「落地」讓部件的整個子樹沿受影面法線平移同一段距離，以所有成員的最低點為準；**有父部件的部件不顯示「落地」**，因為平移無法讓它的關節留在不動的父部件上，整組的「落地」照舊。整組的「還原此物體」與「落地」不變。
- **復原。** 帶動子樹的一次動作（拖圓環、套用、還原此物體、落地）是一步，記下所有被移動的成員，不含群組的 `G`、`c`；與板子、整組及單一部件的步驟放在同一個 50 步堆疊裡依相反順序取消。
- **板子的旋轉中心不變。** 旋轉中心為「點選物體」時，點部件仍取該部件 A 段包圍盒的中心，不取關節。
- 核心、TypeScript 移植與一致性測試集（v8／63 例）不變；沒有 `parent`、`joint` 鍵的場景與 D84 的行為完全相同。

## 10. 修訂（D86，2026-11-03）

本節以引用方式修訂 §2.2 的拖動、§2.3 的數值欄與 §9 的「部件轉動」「數值欄」「圓環與讀數」，上文原文不改；決策為 `docs/DECISIONS.md` D86，合約為 `docs/ARCHITECTURE.md` §5.8 的實作註記。

- **關節限制鍵（網頁專用的場景鍵）。** 有 `parent` 的部件可以帶選用鍵 `objects[i].joint_limit`，值是物件 `{"axis": [x, y, z], "min_deg": m, "max_deg": M}`：`axis` 是恰好三個有限數字、長度不為零且有限的向量，位於**父部件的局部座標**（父部件的網格、基本形體在套用 `transform` 之前的座標）；`min_deg`、`max_deg` 是 [-180, 180] 內的有限數字，至少寫一個，兩個都寫時 `min_deg ≤ max_deg`；沒寫的一邊視為 ±180°，兩邊合起來是整圈（-180 與 180）時視為沒有限制。它和 `parent`、`joint` 一樣只給網頁用：核心忽略它，文件、SVG、警告與一致性測試集都不變；「Download scene」寫回解析後的欄位（`axis` 與寫了的界限，其他屬性不寫）。格式不對的值視為沒有，不報錯也不發警告；`parent` 無效（§9）、根部件或沒有群組的物體帶這個鍵時也沒有限制（鍵仍寫回）。每個部件只有一個限制、一條軸。
- **相對轉動與角度。** 部件 P 相對於父部件 Q 的轉動是 `D = R_Qᵀ·R_P`（兩者都是目前 `transform` 的旋轉矩陣），以 Q 的局部座標表示：P 的局部座標軸與 Q 的對齊時 `D = I`；整組或任何祖先的轉動同時作用在 P 與 Q 上，`D` 不變。角度 `φ` 是 `D` 繞單位軸 `a = axis/|axis|` 的扭轉角（swing-twist 分解的 twist）：取 `D` 的四元數 `(w, v)`（`w ≥ 0`，Shepperd 法），`φ = 2·atan2(a·v, w)`，換到 (-180°, 180°]。`D` 是繞 `a` 轉 θ 時 `φ = θ`，繞垂直於 `a` 的軸轉時 `φ = 0`，與先後順序無關。唯一的奇異點是繞垂直於 `a` 的軸轉 180°（`(a·v, w)` 的長度不超過 1e-9 時 `φ` 取 0，不依捨入誤差）。拖動可以到達它（那是 `κ = 0` 的拖動，`φ` 在它兩側相同），但從它出發時 `φ₀` 沒有定義，見下一項。除了每個物體的 `transform` 沒有任何持久狀態，角度只由 P 與 Q 目前的 `transform` 決定，所以把轉過的部件用「Download scene」存檔再載入，角度不變，限制不能靠存檔再載入疊加。`φ` 在範圍內的定義是 `min − ε ≤ φ ≤ max + ε`，`ε = 1e-9°` 只用來判斷，不用來寫值；`min = -180°` 時 +180° 與 -180° 是同一個姿態，`φ` 讀作 -180°（下限上）；`max = 180°`（沒寫上限）時同理，-180° 讀作 +180°（上限上）。兩條規則不會同時適用，因為兩邊合起來是整圈時沒有限制。
- **拖動時夾限（修訂 §2.2、§9「部件轉動」）。** 拖有限制的部件 P 的圓環時，父部件不動，所以候選姿態的相對轉動是 `D(t) = Rot(e′, t)·D₀`，`e′ = R_Qᵀ·e` 是圓環的世界軸換到 Q 的局部座標，`D₀` 是按下時的相對轉動；`φ(t)` 沿著拖動單調（`dφ/dt = κ/(w² + (a·v)²)`，`κ` 是這次手勢的常數，`D₀ = I` 時 `κ = a·e′`）。吸附後的角度 θ 被夾到第一次碰到邊界的角度：`D₀` 在奇異點上（`(α₁, α₂)` 的長度不超過 1e-9）時，若 `(β₁, β₂)` 的長度也不超過 1e-9，整個手勢都停在奇異點上，θ 取 0；否則候選姿態的 `φ` 在整個手勢上（兩個方向都）是同一個值 `φ⁺ = 2·atan2(β₁, β₂)`（換到 (-180°, 180°] 並照下文的 ±180° 規則），`φ⁺` 在範圍內才照 θ 拖，否則 θ 取 0。所以停在或載入在奇異點的部件，只能用 `φ⁺` 在範圍內的拖動，或還原、復原、整組的動作離開。其餘情形 `|κ| ≤ 1e-9·|(α₁, α₂)|` 時不夾（門檻隨 `(α₁, α₂)` 的長度縮放，所以奇異點附近的姿態照樣夾限）；`φ₀` 已在前方邊界上或之外時 θ 取 0，候選姿態就是按下時的姿態本身（逐位元組相同），不動、不記步驟；否則邊界在 `t_B = 2·atan2(−A, B_c)`（模 360°，取拖動方向上的第一個解），`θ* = sign(θ)·min(|θ|, |t_B|)`。夾過的角度不再吸附。候選姿態仍是 §9 的子樹剛體轉動，只是角度變小；子孫、祖先、兄弟、整組的讀數都照 §9。
- **數值欄拒絕（修訂 §2.3、§9「數值欄」）。** 套用的目標姿態的 `φ` 不在範圍內時拒絕：不算 A 段、不記步驟，三個欄位變紅並保留輸入，面板的關節限制那一行以紅字寫出原因；在範圍內（含剛好在邊界）照 §9 精確套用。不夾限，因為 §9 規定 P 的角度精確等於輸入值、拖動與輸入到達同一姿態。拒絕的訊息一直顯示到下一次套用、Esc、開始拖動、改變選取、載入或任何成功的動作；其間的復原等動作不會把它清掉。不改變姿態的套用不是動作，不檢查。
- **不檢查的動作與範圍外的部件。** 「還原此物體」、復原、落地、整組的所有動作、祖先的轉動，以及沒有限制或沒有父部件的部件，都照舊，不檢查。部件可能在範圍外：載入的 `transform` 已經轉過、範圍不含對齊的姿態，或還原、復原到這樣的姿態（「還原此物體」回到 §9 的目標，即相對於父部件的載入姿態，它的 `φ` 就是載入時的角度）。這時往外拖不動、不記步驟，往回拖自由（可以穿過邊界回到範圍內），套用到仍在範圍外的姿態被拒，不會被悄悄修正。
- **讀數（修訂 §9「圓環與讀數」）。** 面板在樞軸讀數下方多一行，只在選到有限制的部件時出現：「關節限制：繞 blouse 的 (0, 1, 0) 軸 ≤ 11.0°，目前 8.3°」（兩邊都寫時「-30.0°～11.0°」，只寫下限時「≥ -30.0°」），在邊界上時加「（已達上限）」「（已達下限）」，範圍外時加「（超出上限，只能往回轉）」「（超出下限，只能往回轉）」；套用被拒時這一行寫「套用被拒：繞 blouse 的 (0, 1, 0) 軸會轉到 37.0°，超出上限 11.0°」（低於下限時「低於下限 -30.0°」）。角度取 0.1°，用 `toFixed` 的減號（ASCII 連字號 `-`）；被拒的角度與界限取到 0.1° 時相同的話改用 3 位小數（仍相同時 9 位），不會寫成「會轉到 11.0°，超出上限 11.0°」。軸的分量最多 3 位小數。拖動中場景太慢、只更新 3D 代理時，這一行跟著候選姿態更新。
- **限制的意義。** 限制量的是相對於父部件、繞一條軸的扭轉角。它對繞這條軸的單純擺動是精確的；在組合姿態（例如手臂先向前抬再繞這條軸轉，或同時轉另一條軸）或父部件相對於子樹以外的部件移動時，它既不是不碰撞的充分條件，也不是必要條件。
- 核心、TypeScript 移植與一致性測試集（v8／63 例）不變；沒有 `joint_limit` 鍵的場景與 D85 的行為完全相同。
