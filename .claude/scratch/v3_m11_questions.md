## Q3 Esc 的優先序（物件庫、選取、預覽、方程式欄位）

- **位置**：v0.3 §3 第 70 行（Esc：物件庫展開則先收合；否則清除選取）、§2 第 58 行（Esc 也能收合物件庫）。AR 5134（D80 註記：Esc 離開預覽）；`main.ts:295-304`（方程式欄位的 Esc，已 `stopPropagation`）、`main.ts:497-499`（全域 Esc → `set_preview(false)`）；`plane.test.ts:532`。demo `scene_edit_demo.html:1257`（沒有預覽，沒有方程式欄位的優先序）。
- **衝突內容**：Esc 現有三個使用者：方程式欄位、v0.3（收合物件庫、清除選取）、D80（離開預覽）。v0.3 只排了後兩個中的前兩項。三份分析報告的建議順序並不一致：
  - 報告 a：方程式欄位 > 物件庫 > 選取 > 預覽。
  - 報告 c：方程式欄位 > 物件庫 > 預覽 > 選取。
  - 報告 d：物件庫 > 預覽 > 選取；文字欄位保留自己的 Esc。
  共同點只有「方程式欄位最優先、物件庫次之」。
- **建議**：每按一次 Esc 只做一件事，由內而外：(1) 方程式欄位有焦點 → 欄位自己的 Esc（已 `stopPropagation`，不傳到 window，維持）；(2) 物件庫展開 → 收合；(3) 有選取 → 清除選取；(4) 預覽中 → 返回編輯。理由：選取是預覽內的狀態，先收掉內層狀態再離開模式，行為可預期，也不會讓「在預覽按 Esc」同時丟掉選取。若使用者認為「Esc 離開預覽」比保留選取重要，改為 (3)(4) 對調；兩種都只是 `main.ts` 全域 keydown 的條件順序。拖曳進行中（物件、把手、圓環、箭頭）的 Esc 不做事，與「預覽在拖曳中被拒絕」一致。
- **影響範圍**：`main.ts` 全域 keydown（新增物件庫與選取分支）；`plane.test.ts:532` 的正規表示式；新增測試列「Esc 優先序」。DEC 寫在 D81（選取）或 D84（物件庫）其中一條。
- **狀態**：[confirm]（預設：欄位 > 物件庫 > 選取 > 預覽）

## Q25 錨點與包圍盒的定義（§0.1、§4.2）

- **位置**：v0.3 §0.1 第 27–28 行（錨點＝底面中心；限制 z_b ≥ 0）、§4.2 第 105 行（物件頂端中心、物件高度）、§3 第 81 行與 §4.3（「包圍盒中心」）。合約 §2.1（局部座標系：`world = R·local + position`）。報告 b §2；報告 d 的 A5、V1。
- **衝突內容**：「錨點 = 底面中心、z_b = 0 在地面上」對八個預設物件成立，但一般情況不成立：
  - box、cylinder、cone：錨點是底面中心。
  - prism：錨點是多邊形局部 (0,0)，不一定是形心（預設物件取形心）。
  - **sphere：錨點是最低點（球心正下方 r），不是球心**（驗證過：r = 0.5 的球包圍盒 z ∈ [0, 1]）。
  - mesh：資料的局部原點，可在任何位置（`multilight_mesh_fallback_shared_edges` 的外殼 z_min − z_b = +0.47；`mesh_noisy_l_ground_contact` 為 −1e-7）。
  - 傾斜物件（`rotation_deg` 的 x、y 分量 ≠ 0）：錨點不是最低點（例：`arc_pairing_u_on_side` 的 z_min − z_b = −1）。

- **建議**：
  - 把 §0.1 的錨點與底面高度改寫（建議措辭，寫進合約註記）：「錨點：物件的 `transform.position`，即基元局部座標原點——box、cylinder、cone 為底面中心；prism 為多邊形局部原點（預設物件取形心）；sphere 為最低點（球心正下方 r）；mesh 為其資料的局部原點。底面高度 z_b 是錨點的 z；未傾斜的基元 z_b = 0 時恰好放在地面上。」

  - 垂直拖曳的垂直線仍通過按下時的錨點（只有 z_b 被編輯）。
  - 放置與避讓的「水平包圍矩形」同樣取世界 AABB（旋轉物件）。

## Q34 物件庫與刪除的小處

- **位置**：v0.3 §2 第 48–61 行、§6 第 159 行。demo `scene_edit_demo.html:77-87, 1242-1249, 804`。報告 d 的 L2、L4、L7、L8、X2、A12、A20。
- **項目**：
  1. **窄螢幕點側邊欄以外會收合**：demo 用 `document` 的捕獲階段 `pointerdown`，不消耗事件，所以那次點擊也會到達畫布（可啟動軌道、選取物件或清除選取）。v0.3 沒規定。建議：收合那一下的點擊**被消耗**（不傳到畫布），且不得吞掉旁觀窗的 pointerdown 之外的其他合法互動。
  2. **窄螢幕斷點**：JS 用視窗寬度 `window.innerWidth < 880`；兩窗並排或疊放則看窗格寬度，兩者在 880 附近可能不同步。建議以視窗寬度為準（v0.3 §2 寫「寬度 < 880 px」）。
  3. 側邊欄展開時分頁鈕 `visibility: hidden`（demo）：v0.3 沒寫；可維持。
  4. 焦點管理：展開不搬焦點、收合不還焦點、不使用 `inert`；v0.3 只要求 Tab/Enter/空白鍵。建議：最低限度的無障礙——收合時側邊欄 `inert`（Tab 不進入），關閉時焦點回到分頁鈕（合約 §5.8.7、§5.8.10 的預設，比 demo 多這兩項）。
  5. **停用的刪除鈕**只有 hover 提示，觸控看不到。v0.3 §6 要「停用並顯示提示」，應讓提示文字可見（顯示在晶片內，「場景至少要有一個物件」）；按 Delete 只剩一個物件時同樣顯示提示（`#notices` 區）。
  6. 圖塊「最多 6 個中文字」只在 CSS 以省略號強制；「縮圖以同一個斜視角度繪製」demo 做不到（手繪、角度不一致），M11 的縮圖資料表要自己遵守。
  7. 分頁鈕在 `.stage`（包兩窗）的左緣、頂端 56 px、直排文字；`aria-expanded`、`aria-controls`。物件庫**覆蓋**兩窗，不推擠畫布（`#viewport` 不改尺寸）。
- **影響範圍**：`library.ts`、`main.ts`、`ui.ts`、`index.html`、`style.css`；測試：預設折疊、窄螢幕自動收合、圖塊 `aria-label`「加入：名稱」。
- **狀態**：[confirm]（第 1、5 點需要確認；其餘預設採建議）
